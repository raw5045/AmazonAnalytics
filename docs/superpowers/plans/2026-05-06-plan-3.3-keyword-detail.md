# Plan 3.3 — Keyword Detail Page

Owner: Reese
Status: Spec for review
Predecessor: Plan 3.2 (Keyword Explorer) — complete and shipped
Successor: Plan 3.4 (Saved Views + Watchlists)

## Goal

When a user clicks a keyword in the explorer, take them to a dedicated detail page that shows that keyword's full **52-week story**: how its rank moved, what products dominated it, how the fake-volume signal evolved, and what raw data we have for it.

This is the second user-visible page in the analytics product. Like the explorer, it's read-only — saving / watchlisting comes in 3.4.

## URL contract

```
/explorer/keyword/<search_term_id>
```

- `<search_term_id>` is a UUID
- No query params for V1 (the page is "show everything")
- Both `admin` and `standard_user` can access (same auth gate as `/explorer`)
- Click-through from the explorer row's "Search term" column links here

## Out of scope (explicitly)

- Editing/saving views — Plan 3.4
- Watchlist add — Plan 3.4
- Cross-keyword comparisons (overlay multiple keywords on one chart) — defer
- Mobile-optimized layout — desktop-first; mobile is "works but not polished"
- Custom time-range picker (just always show all 52w; we can add range later)
- Notes / annotations on individual weeks
- Export this keyword's history as CSV

## Data model

### What we read

A single query against `keyword_weekly_metrics` for this term, plus the `keyword_current_summary` row for at-a-glance stats.

```sql
-- Header summary (1 row)
SELECT kcs.*, st.search_term_raw, st.search_term_normalized
FROM keyword_current_summary kcs
JOIN search_terms st ON st.id = kcs.search_term_id
WHERE kcs.search_term_id = $1;

-- Full history (up to 52 rows)
SELECT
  k.week_end_date,
  k.actual_rank,
  k.top_clicked_product_1_asin, k.top_clicked_product_1_title,
  k.top_clicked_product_1_click_share, k.top_clicked_product_1_conversion_share,
  k.top_clicked_product_2_asin, k.top_clicked_product_2_title,
  k.top_clicked_product_3_asin, k.top_clicked_product_3_title,
  k.top_clicked_category_1,
  k.keyword_in_title_1, k.keyword_in_title_2, k.keyword_in_title_3,
  k.keyword_title_match_count,
  k.fake_volume_severity,
  k.fake_volume_eval_status
FROM keyword_weekly_metrics k
WHERE k.search_term_id = $1
ORDER BY k.week_end_date;
```

Both queries hit the existing `kwm_term_week_idx` (search_term_id leading) and the kcs PK. Sub-100ms each on warm cache.

### Edge case: keyword not in kcs

The keyword might be in `search_terms` + `kwm` but not in `keyword_current_summary` — this happens when the term is dormant (last seen > 28 days ago). We should still render the page using `kwm` data, just with a banner "This keyword has been dormant since <date>."

### Edge case: keyword not found at all

404. Render a "Keyword not found" message with a link back to the explorer.

## Charting

**Library: Recharts.**

Why: composable React components, plays well with Next.js server components (charts render client-side, data fetched server-side), small enough bundle (~80KB gzipped), built-in for the line chart + reference lines + tooltip patterns we need.

Alternatives considered:
- **Chart.js / react-chartjs-2** — also fine, similar bundle size. Recharts is slightly more declarative which fits the rest of the codebase.
- **Apache ECharts** — overkill for this scope, larger bundle.
- **Plain SVG** — possible but reinventing tooltips, axes, etc.

### Inverted Y-axis for the rank chart

In Amazon SFR data, `rank = 1` is the most-searched term, so visually we want low numbers at the TOP of the chart (the "best" position). Recharts supports `<YAxis reversed />`.

### Reference lines

Plot horizontal lines at 10,000 / 50,000 / 100,000 / 500,000. Gives the user instant context for whether a keyword is "top-tier" or "long-tail."

### Unranked weeks

Recharts can render gaps in a line chart by emitting `null` for missing weeks. We'll iterate over the full 52-week calendar and emit null where `kwm` has no row.

## Open questions

1. **Default chart time window** — show all 52w, or default to last 13w with an option to expand? V1 default to all 52w; we can add a range toggle later if it's too dense.

2. **Multi-product timeline** — V1 only shows top product #1. Should #2 and #3 also get their own timeline sections, or just the raw data table at the bottom? My read: only #1 in dedicated section, #2/#3 visible in raw table. We can add separate sections later if useful.

3. **What does "Active for X of last 52 weeks" actually count** — weeks where the term has any kwm row, regardless of rank? I'd use that. (vs "weeks where the term was ranked in the top 1M" or similar.)

4. **Fake volume strip color for unknown / NULL severity** — gray with a tooltip explaining "Could not evaluate (missing click_share or conversion_share)." OK?

5. **Sort order of the raw data table** — most-recent first, or oldest first? My pref: most-recent first (matches reading order of "what's happening now").
